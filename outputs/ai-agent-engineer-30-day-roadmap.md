# Java 后端 → AI Agent 工程师：30 天学习路线图

默认投入：每周 20 小时（工作日 3 小时、周末各 5 小时）。每天只有 2 小时时，把一个 Day 拆成两天；不要删掉评测、部署和复盘。

本月只用 **Python**。Java 与 TypeScript 都不是前置条件：Java 可在第二个月接入真实业务，TypeScript 仅在需要 Node 或前端时再补。

学习方式：先用小练习掌握一个概念，再在第 4 周将它们整合为 Python 命令行作品。作品是验证学习的载体，不是现在就要完成的设计任务。

综合练习：**生产故障诊断 Agent**。它读取模拟日志、指标和运行手册，给出带证据的诊断报告；高风险建议只标记为人工审批，不执行任何动作。

## 能力地图

```text
模型 API / JSON 输出
        ↓
工具调用 / RAG
        ↓
状态、记忆、Agent 编排、MCP
        ↓
评测、追踪、可靠性、安全、人审
        ↓
Docker、CI、演示、技术表达
```

## 不可省略的验收线

第 30 天前，你应能出示：

- 一个可运行的 Agent 服务，至少有 3 个工具、一次多步调用和人审路径。
- 30+ 可重复执行的评测案例；正常场景成功率目标 ≥85%，危险操作拦截率 100%。
- 调用追踪，能定位一次失败来自模型、工具、检索还是编排。
- Docker 化启动方式、自动化测试/评测、架构图和清晰 README。
- 一个 5 分钟可讲清楚“为什么这样设计”的演示。

## 技术选择原则

1. Python 是本月唯一需要投入的语言。使用 OpenAI 兼容 API 与本地 CLI，避免因跨语言或前端分散注意力。
2. 第一个月不必深究框架。工具契约、状态、评测和安全是可迁移的核心能力。
3. 先做确定性 workflow，再只把确实需要判断的节点交给模型。
4. 任何有副作用的工具都要走“提案 → 人审 → 执行”，不能让模型直接拥有执行权限。
5. Java/Spring Boot 留作第二个月的扩展：把真实业务 API 或 MCP 工具接入已经验证过的 Python Agent。
