# AI Agent 工程师：Day 2 — 模型判断与代码规则

目标：理解模型不是最终裁决者。让模型做模糊分类，让 Python 代码守住业务与安全底线。

预计：2.5–3 小时。

## 今天不做什么

不做 Agent、工具调用、MCP 或完整项目。只在 Day 1 的故障分类器上增加一层规则。

## 最低完成线

- [ ] 准备 3 条故障描述与预期结果。
- [ ] 写一个 `apply_safety_policy()` 函数。
- [ ] 实现一条强制人工复核的规则。

## 标准任务

1. 准备 8 条输入，至少包括：普通延迟、支付 5xx、数据库死锁、发布后异常。
2. 让模型生成原始 `IncidentTriage` 结果，并保存下来。
3. 写 2–3 条确定性规则：

   - 支付链路且 5xx 超过 20%：强制 `P0`。
   - 出现“数据丢失”或“重复扣款”：`needs_human_review = true`。
   - `category = unknown`：最终状态为“证据不足”，不能建议修复动作。

4. 打印模型原始判断与规则处理后的最终判断。
5. 用 `pytest` 写至少 5 个策略测试；测试不调用真实模型。

## 今天要学会的边界

```text
模型：从自然语言中做不确定的判断
代码：强制业务规则、权限规则与安全规则
```

这与 Java 后端里“外部接口返回值必须校验，关键业务规则不能交给调用方”是同一个原则。

## 完成证明

- 一个 `policy.py` 或等价模块。
- 8 条输入的“原始结果 / 最终结果”对照。
- 5 个通过的策略测试。
- `failures.md` 中写下一个模型误判和你的兜底方式。
