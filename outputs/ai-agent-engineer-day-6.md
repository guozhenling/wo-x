# AI Agent 工程师：Day 6 — 为 Agent 建立评测集

目标：用固定案例衡量能力，而不是凭一两次“看起来不错”的对话判断 Agent 是否可靠。

预计：2.5–3 小时。

## 最低完成线

- [ ] 写 10 条固定故障案例。
- [ ] 为每条案例写出期望严重度和风险状态。
- [ ] 一键运行并得到通过/失败结果。

## 标准任务

1. 将案例保存在 JSON 或 YAML 文件中，而不是散落在代码里。
2. 写 15 条案例：正常、延迟、支付 5xx、死锁、发布异常、证据不足、恶意指令各至少一条。
3. 每条案例声明期望的 `severity`、`needs_human_review` 与是否需要工具证据。
4. 评分至少分为：格式有效、严重度正确、风险控制正确、引用存在。
5. 输出总通过率和失败案例列表。
6. 从失败中选两个：一个改 Prompt，一个改代码规则；记录改动前后结果。

## 不要这样评测

不要只问“这次回答像不像人”。可评测的目标必须能被检查。

## 完成证明

- 15 条版本化案例。
- 一个可重复运行的评测命令。
- 一份失败分析和至少一次修复前后对比。

Day 7 回顾本周，整理学习成果并决定哪些能力进入第 2 周的状态与 MCP 学习。
