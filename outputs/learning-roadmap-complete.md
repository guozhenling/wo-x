# AI Agent 工程师 30 天学习路线图（完整版）

## 📋 课程概览

**学习目标**：在一个月内，从 Java 后端开发工程师转型为能够独立设计、实现、评测并部署 AI Agent 的工程师

**项目成果**：故障分类器 - 可展示的生产级 AI Agent 系统

---

## 第一周：基础概念与核心能力（Day 1-7）

### Day 1 - Agent 是什么？第一个 Structured Output
**学习目标**：
- 理解 Agent 与聊天机器人的本质区别
- 掌握 Structured Output（JSON）
- 用 Pydantic 校验模型输出

**核心内容**：
- Agent vs 聊天机器人对比
- 为什么需要结构化输出
- 完整示例：故障分类器原型

**产出**：能稳定输出 JSON 的分类器

---

### Day 2 - 为什么需要 Policy 规则？
**学习目标**：
- 理解模型不可信
- 掌握确定性规则与模型判断的边界
- 实现 PolicyEngine

**核心内容**：
- 模型会犯什么错
- Policy 规则的作用
- 什么该用规则，什么该用模型

**产出**：带规则兜底的分类器

---

### Day 3 - 第一个工具：日志搜索
**学习目标**：
- 理解什么是工具（Tool）
- 掌握只读工具设计
- 实现 search_logs

**核心内容**：
- 工具的三要素
- 安全边界
- 工具定义（Tool Definition）

**产出**：可查询日志的工具

---

### Day 4 - Tool-Calling Loop（工具调用循环）
**学习目标**：
- 理解完整的工具调用流程
- LLM 如何主动调用工具
- 实现多轮对话

**核心内容**：
- Tool-Calling Loop 流程
- 消息格式（4 种 role）
- 调用次数限制

**产出**：会主动查日志的 Agent

---

### Day 5 - 第二个工具：Runbook 检索
**学习目标**：
- 理解 Runbook 作用
- 掌握关键词匹配算法
- 实现 Runbook 检索

**核心内容**：
- Runbook 是什么

- 匹配算法

**产出**：能推荐处理方案的功能

---

### Day 6 - 调用轨迹管理
**学习目标**：
- 理解轨迹的作用

**核心内容**：
- 为什么需要轨迹

**产出**：可追溯的调用记录

---

### Day 7 - 第一周总结与集成
**学习目标**：
- 整合所有模块

## 🎯 学习建议

### 学习节奏
- **每天 2-3 小时**
- 不要跳跃，按顺序学习
- 每周完成作业

### 完成标准
- **第一周**：能独立实现带工具的 Agent
- **第二周**：能处理错误和优化性能
- **第三周**：能评测和改进系统
- **第四周**：能部署和展示项目

### 如何使用这些文档
1. **每天开始前**：阅读学习目标（5 分钟）
2. **学习概念**：理解 What, Why, How（15 分钟）
3. **运行示例**：理解代码（30 分钟）
4. **动手练习**：从 Level 1 到 Level 3（1-2 小时）
5. **完成检查**：确认理解（10 分钟）
